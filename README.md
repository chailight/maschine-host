# Maschine Host

A portable, headless host for the full-size Native Instruments Maschine MK2, initially targeting Raspberry Pi OS (64-bit) and macOS.

The host reads a Maschine Controller MK2 (`17cc:1140`) and writes its lamps and both LCDs. Groups A–H select the playable instrument. The buttons above the displays select a control category, and the encoders send MIDI. Start with `docs/operator-quickstart.md` and `docs/bitbox-control-pages.md`.

## Default configuration

`docs/example-config.yaml` is the default setup. It targets a Bitbox Micro running the community extended firmware, not the stock module. Controller numbers, mode names, and what each encoder does are defined by that patch. The host proposes a few extra controllers for the module to learn, listed in `docs/bitbox-control-pages.md`. The host does not read parameter values back from the module.

Firmware source and the controller reference: https://github.com/modularpatcher/bitbox-micro-fw-patch

```sh
cargo run -- --config docs/example-config.yaml
```

## Host features

These are generated by the host. They are not controllers in the Bitbox firmware. Add a short note here when another one is built.

### EQ LFO

On the second EQ page (EQ, then Right). Encoder 1 remains Slope. Encoders 2–5 are speed, depth, shape, and destination.

Speed is in hertz and does not follow a tempo. Fully left is stopped, the middle is 1 Hz, and fully right is 10 Hz. Depth is how far the chosen control swings either side of its current value. Shape is Sine, Triangle, Square, or Saw. Destination starts at None. The other three positions are the current EQ mode's three play controls, shown by those controls' names. On Phaser they are Sweep, Depth, and Spread. A position with no control, such as Tilt's fourth encoder, shows N/A and sends nothing.

The knob position on the first EQ page stays put. The host sends the moving value around it. Choosing None sends that stored value once so the module settles. This is not the Bitbox pad LFO.

### Pad Mode screen

Pad Mode toggles a setup screen titled PAD MODE for the selected group. Both displays show the group letter and name. The columns are velocity curve, scale, root note, octave, and pad type. Encoders 1–5 change those values for the session, and a value moves once every twenty encoder clicks. The curve steps through 0.5, 1, and 2 and stops at either end. The scale list is notes, then the western modes ionian, dorian, phrygian, lydian, mixolydian, aeolian, and locrian, then major pentatonic, minor pentatonic, and chromatic. It is offered on every group. The root is a note name, with C4 at MIDI note 60, and it is kept when the scale is set back to notes. Octave uses the existing offset on every group, including one-shot. An omitted pad type loads as sample. The type can also be granular, clip, slicer, or none. Sample is also the choice for a multisample cell. Leaving the screen returns to the current control page. PERFORM encoders 5–8 and the PAD pages then follow the chosen type. The choice is not written to the configuration file or to the Bitbox.

## Later: matching presets

Keep a local copy of each Bitbox preset. Loading a preset from the Maschine controller will send the program change that loads it on the module and will load the matching local `preset.xml`, so the host's pad types and the rest of the group layout match the preset that is playing. Until that library exists, pad type on the controller is set by hand. That choice shows or hides host controls and does not change the module or the preset file.

## Development with OpenSpec

This repository contains an initial OpenSpec change proposal under `openspec/changes/maschine2-host-mvp/`. Install and initialize a compatible version of OpenSpec in the repository, then ask Codex or Cursor to review the proposal, design, specifications, and tasks before implementation. OpenSpec CLI conventions may vary by version; preserve the files if initialization offers to overwrite them.

Suggested agent prompt:

> Read openspec/changes/maschine2-host-mvp/proposal.md, design.md, specs/ and tasks.md. Review the proposed architecture against the upstream MK2 HID implementations and the current OpenSpec conventions. Resolve the hardware-spike gates first, document evidence, then implement the MVP incrementally with tests. Do not assume undocumented USB, LCD, or MIDI feedback capabilities.

## Boundaries

This is not a Zynthian fork, a Maschine software clone, or an autonomous mixing system. The initial product supports MK2 performance control, external MIDI destinations and a small local sampler. Audio listening and Pd are deferred.
